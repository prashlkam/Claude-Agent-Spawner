# Weekly Research Brief

Researches a topic across the web and the team wiki, then produces a one-page brief every Monday.

`v0.3.0` · generated by [Agent Spawner](https://github.com/) from an `AgentSpec`.

## Install

```bash
/plugin marketplace add ada/weekly-research-brief
/plugin install weekly-research-brief@weekly-research-brief
```

> This plugin ships with `defaultEnabled: false` because it costs money or reaches external services. Enable it explicitly per project.

## What it does

Produce a one-page research brief on an assigned topic each week, grounded in sources a reader can check.

### Success criteria

- Every claim has a source link
- The brief fits on one page
- Contradictions between sources are called out rather than averaged away

### Out of scope

- Making recommendations or investment calls
- Summarising sources behind a paywall the team cannot access

## Workflow

1. **Scope the question** — Turn the assigned topic into three answerable sub-questions.
2. **Gather sources** — Search the web and the team wiki for primary sources.
3. **Fact-check the draft** — Verify every claim against the recorded sources before the brief goes out.
4. **Write the brief** — Assemble the one-page brief from the verified findings.

## Sub-agents

| Agent | When it is used | Model | Runs |
|---|---|---|---|
| `web-researcher` | Use when the topic needs public sources. Searches the open web and returns claims with URLs. | sonnet | foreground |
| `wiki-researcher` | Use when the topic may already be covered internally. Searches the team wiki through the GitHub connector. | sonnet | foreground |
| `brief-writer` | Use once research is in hand. Turns collected findings into the one-page brief and fact-checks it. | opus | foreground · own worktree |

### Orchestration

- Stage 1 — parallel: web-researcher, wiki-researcher
- Stage 2 — series: brief-writer

**Joining results:** Merge the two research sets, drop duplicates by URL, and hand the combined list to brief-writer.

## Connectors

### `github` — GitHub

Reads the team wiki and issues.

Docs: https://github.com/modelcontextprotocol/servers

Transport: `stdio` · Tools: `mcp__github__search_repositories`, `mcp__github__get_file_contents`

Environment variables:
- `GITHUB_TOKEN` — A fine-grained token with read access to the wiki repository. **· secret, never commit this**

Copy `.env.example` to `.env` and fill in the values. **No credentials are stored in this bundle** — the MCP manifest only contains `${VAR}` placeholders.

## Recommended permissions

A plugin's `settings.json` cannot carry permissions. Paste this into the consuming project's `.claude/settings.json`:

```json
{
  "permissions": {
    "allow": [
      "Read(**)",
      "Write(briefs/**)",
      "mcp__github__search_repositories",
      "mcp__github__get_file_contents"
    ],
    "deny": [
      "Read(.env)",
      "Write(.env)"
    ]
  }
}
```

## Per-agent MCP access

Plugin-packaged agents may not declare their own `mcpServers` or `permissionMode` — Claude Code rejects those keys for security reasons. The connectors in `.mcp.json` are available to the whole project, and each agent narrows them through its `tools` allowlist.

If you need a connector scoped to one agent only, define that agent locally in `.claude/agents/` in your project rather than through this plugin.
